# Returns Policy

This document defines the Sequo Customer App return and refund experience.

## Core Rule

Returns are allowed within 72 hours of delivery.

The customer must drop the returned product at a Point de Relai. Refunds trigger automatically as soon as Sequo inspects and accepts the returned product.

This 72-hour rule replaces older legacy references to longer return windows.

## Eligibility Window

| Event | Rule |
| --- | --- |
| Delivery completed | Starts the 72-hour return window |
| Return request opened | Must happen before the 72-hour deadline |
| Point de Relai drop-off | Customer must use the return reference/PIN generated by Sequo |
| Sequo inspection accepted | Refund trigger starts automatically |
| Sequo inspection rejected | Customer sees rejection reason and support path |

The app must display the exact return deadline using the delivery timestamp.

Example:

```text
Delivered: Monday 14:30
Return request deadline: Thursday 14:30
```

## Return Flow

1. Customer opens order history.
2. Customer selects a delivered order.
3. App checks whether delivery was within the last 72 hours.
4. Customer selects item or items to return.
5. Customer chooses a return reason.
6. App shows drop-off instructions for Point de Relai.
7. Backend creates return reference and return PIN.
8. Customer drops the item at a Point de Relai.
9. Relay partner validates return reference and PIN.
10. Sequo collects or receives the returned product.
11. Sequo inspects the product.
12. If accepted, refund is triggered automatically.
13. Customer sees refund status until complete.

## Return Reasons

Recommended customer reasons:

- Wrong product.
- Damaged product.
- Missing item.
- Size or variant issue.
- Product not as described.
- Quality concern.
- Delivery damage.
- Other.

The customer may be asked for photos, but the return is completed through Point de Relai drop-off and Sequo inspection.

## Product Condition

The product must be inspectable by Sequo.

Inspection should verify:

- Product identity matches the order.
- Product is present.
- Serial number or variant matches when applicable.
- Damage or issue matches the customer reason.
- Product was not intentionally damaged or substituted.
- Food/perishable safety rules are respected when applicable.

Acceptance or rejection must be recorded with an auditable reason.

## Refund Trigger

Refunds trigger automatically as soon as Sequo inspection accepts the returned product.

Rules:

- Relay partners do not issue cash refunds.
- Support agents do not need to manually start a standard accepted refund.
- The backend creates the refund event immediately after accepted inspection.
- Customer sees `Refund processing` and then `Refund completed`.
- Refunds follow the approved non-cash provider or ledger path.

## Non-Cash Policy

Sequo does not support cash withdrawal or cash refund pickup.

Refunds must go through approved digital paths such as the original payment provider flow or an internal non-withdrawable ledger if business policy supports it.

## Point De Relai Requirements

The customer return screen must show:

- Return reference.
- Return PIN or scannable code.
- Eligible Point de Relai locations.
- Drop-off deadline.
- Packaging instructions.
- Support contact.

The relay partner validates:

- Return reference.
- PIN.
- Product handoff.
- Timestamp.
- Storage slot or handoff record.

## Customer Statuses

| Status | Meaning |
| --- | --- |
| Return available | Order is within the 72-hour window |
| Return requested | Customer created a return request |
| Awaiting drop-off | Customer must drop at Point de Relai |
| Dropped at Point de Relai | Relay validated handoff |
| Under Sequo inspection | Sequo is checking the returned product |
| Return accepted | Inspection accepted the return |
| Refund processing | Refund was automatically triggered |
| Refund completed | Refund path completed |
| Return rejected | Inspection rejected the return |
| Return expired | 72-hour window passed |

## Edge Cases

| Case | Expected behavior |
| --- | --- |
| Customer requests after 72 hours | App blocks standard return and offers support contact if policy allows exceptions |
| Customer starts return but does not drop off | Return remains awaiting drop-off until backend expiry policy closes it |
| Wrong item returned | Inspection rejects or routes to support investigation |
| Product damaged during delivery | Sequo can accept and trigger refund after inspection |
| Product damaged by customer | Inspection can reject with reason |
| Payment refund fails | Order shows refund issue and support receives alert |

## Backend Requirements

- Return eligibility is server-authoritative.
- Delivery timestamp must be immutable after completion except audited admin correction.
- Return references and PINs are single-use.
- Inspection acceptance triggers refund automatically.
- Refund events must be idempotent.
- All return decisions must be auditable.

## Acceptance Criteria

- Customer can request a return only within 72 hours of delivery.
- Return must be dropped at Point de Relai.
- Customer receives return reference and PIN.
- Sequo inspection acceptance automatically triggers refund.
- No cash refund or cash withdrawal path appears in the customer app.
- Customer can track every return/refund state.
